## 2. §5 감사 체크리스트 — 6항목 상세

### 체크 1. §2.8 FF drops waterfall — **부분구현 (Griddler 정의와 다른 물건)**

구현된 것 (`_tab_waterfall`, 11479-11591):
- 단일 시뮬레이션의 `losses()` 분해를 PCE %abs 누적 막대로 표시 (11494-11517)
- 채널: Optical(shade) / Recomb / Shunt / Grid R(Pe+Pf_finger+Pf_busbar+Pc+Pj) — 11496-11504
- 기준선 `PCE_ref = PCE_act + 모든 손실 채널` 의 1차 복원 (11507)

**빠진 것 — 매뉴얼이 규정한 6단계 순차 재시뮬레이션이 전혀 없음**

| Griddler 단계 | 코드 내 존재 여부 |
|---|---|
| 1. Edge recombination off | 없음 (edge recomb 항 자체가 모델에 없음) |
| 2. Passivated front J01 → median 치환 | 없음. 공간 분포는 `SpatialMap`(3169)으로 가능하나 median 치환 시나리오 없음 |
| 3. n=2 diode off | 없음. J02는 항상 활성 (6985-6986) |
| 4. Metal contact recomb 증가분 off | 없음. `J01_metal`/`J02_metal`을 pass 값으로 치환하는 경로 없음 |
| 5. Shunt conductance off | 시나리오로는 없음. 손실 막대로만 표시 (11498) |
| 6. 무저항 ideal FF 계산 | 없음. `FF_ideal = PCE_ref` 로 **변수명만 재사용** (11520) |

**두 가지 귀속 규칙**
- "잔차 전부를 직렬 저항에 귀속" — 미적용. 현 구현은 직렬 R을 `losses()`로 **직접 계산**해 합산한다 (11504). 물리적으로는 오히려 우월하나, Griddler 수치와 1:1 대조가 불가능하다.
- "성분별 비율 = MPP 전력 소산 비율" — 직접 계산이므로 이 가정 자체가 불필요. 결과적으로 성분 분해는 이미 있다 (11575 부근 summary 패널).

**결론**: 랩미팅에서 언급된 "edge margin 증가 시 FF 감소의 원인 규명"은 현 구현으로도 가능하다 (Pe / Pf_busbar / Pf_finger / Pc가 분리되어 있음). 다만 Griddler 출력과의 **대조 검증**이 목적이라면 6단계 시나리오 러너를 별도로 만들어야 한다.

> **후속 (2026-08-19, v28.66)**: 위 표의 "빠진 것"을 *결함 목록*으로 읽지 않도록
> 규약 문서를 따로 뒀다 — **`docs/ff_waterfall_convention.md`**. 특히 2단계
> (중앙값 치환)는 미구현이 아니라 **적용 대상이 아니다**(0D 재구성을 위한
> 장치인데 우리 막대는 손실 적분의 항이다). 이 감사가 정확히 지적한
> "물리적으로는 오히려 우월하나 1:1 대조가 불가능하다"를 그 문서가 확장한다.
>
> 같은 탭의 **J0 Decomposition 패널**은 v28.65까지 `DP` 스칼라를 직독해 공간
> 분포 맵을 조용히 무시하고 있었다 — v28.66에서 `FESTSolver.j0_decomposition`
> 으로 배선했다. 이 감사 시점에는 발견되지 않았던 항목이다.

### 체크 2. §2.7 Metal Optical Transparency — **미구현**

- `CellGeometry.shading_fraction(w_f_opt=None, w_b_opt=None)` (1287-1291)은 optical width 인자를 받는 **시그니처만** 갖는다. 기본값은 물리폭 `self.w_f` / `self.w_b`.
- 전체 호출자 조사 결과, optical width를 **물리폭과 다른 값으로 전달하는 곳이 하나도 없다**:
  - 3962-3964 — 케이스 폭 `wf`, `wb_case` (FEM 저항 계산에 쓰는 바로 그 물리폭)
  - 6898 — `losses()` 내부, 동일한 케이스 폭
  - 그 외 리포트/비교 탭 및 `front_electrode/adapter.py`, `scripts/rerun_baseline.py` — 전부 물리폭
- 동일한 폭이 **접촉 컨덕턴스**(3934-3946)와 **발전량 스케일**(3956-3968)에 동시에 들어간다. 즉 physical/optical 분리가 구조적으로 없다.
- GUI에도 해당 입력란이 없다 (`transparen` 검색 결과는 전부 `fg_color="transparent"`).

**유일한 부분 대체 — busbar recovery factor** (`front_electrode/adapter.py`)
- `effective_busbar_shading = raw × (1−f)`, `recovered = raw × f` (12-17행, 63-88행)
- 그러나 (a) **busbar에만** 적용되고 finger는 제외됨을 명시 (20-23행), (b) FEM 재계산 없는 **사후 line-item** 보정이라 광전류에 피드백되지 않음을 소스가 스스로 기술 (25-29행), (c) 기본값 0.25는 "보편 물성 아님"으로 태깅 (50행).

**결론**: 문서 §2.7이 "정공법"으로 지목한 MBB 분절 busbar 모델링은 현재 불가능하다. finger 쪽은 회수 개념조차 없다.

### 체크 3. §2.4 Print method (busbar–반도체 접촉 여부) — **미구현**

- `print_method` / `dual_print` 등 어떤 이름으로도 코드에 존재하지 않는다 (repo-wide 0건).
- 모델은 **single print로 하드코딩**되어 있다:
  - `is_metal = is_finger | is_busbar | is_pad` (2261, DXF 경로도 동일 3036)
  - 접촉 컨덕턴스가 모든 금속 노드에 부여됨: `self._Gc[self.ism] = ...` (3934)
  - `metal_rects_front()`가 busbar 사각형을 포함 (1310 이하) → `compute_metal_frac` (2374) → 금속 아래 재결합 가중 `J01_top_metal * mf` (6985-6986)
- 따라서 busbar는 항상 (a) 반도체와 접촉하고 (b) metal-induced recombination을 유발한다. Dual print(floating busbar)를 표현할 수단이 없다.

**영향**: 문서 §4 용어 대응표가 지적한 대로 contact 손실과 재결합 손실을 동시에 과대평가할 수 있다. 특히 dual print 셀을 모델링하면 `Pc`(6893)와 `P_recomb`(6990 부근) 양쪽에서 busbar 기여가 허위로 계상된다.

### 체크 4. §2.5 mesh 밀도 기준 (4노드 규칙) — **자동 검사 없음**

- 존재하는 진단은 두 가지뿐이고, 둘 다 Griddler 기준과 무관하다:
  - `mesh_quality_metrics` (1786-1829) — 삼각형 최소각, P05 각, 최대 aspect ratio
  - `mesh_distribution_metrics` (1832-1890) — 좌우/상하 대칭성, centroid 편향, peak bin 밀도, 사분면 불균형
- **"busbar 사이 finger를 따라 최소 4노드" / "finger 사이 최소 4노드"를 판정하는 코드는 없다** (`NodesPerFinger` 계열 식별자 0건).
- 관련 재료는 있다: `add_grid_features`가 finger 축을 `x_segments`로 (2094), busbar 축을 `y_segments`로 이산화하므로 실현 노드 수를 사후 산출하는 것은 가능하다.

**권고**: `mesh_quality_metrics`에 `NodesPerFingerSpan` / `NodesBetweenFingers` 두 항목을 추가하면, "M10과 소면적 셀의 수렴 방향이 서로 반대"였던 현상을 이 기준으로 즉시 재점검할 수 있다.

### 체크 5. §7 Tandem non-overlapping area Jsc — **미구현**

- `non-overlap`, `nonoverlap`, `top_area`, `area_top` 등 어떤 형태로도 repo-wide 0건.
- 현 모델은 top/bottom 셀이 **동일 면적**임을 암묵 가정한다. `illum_frac`(3968)과 rear 대응물은 전극 금속에 의한 차폐만 구분하며, subcell 면적 차이를 표현하는 자유도가 없다.
- 실험용 tandem에서 top cell이 작은 경우 Jsc가 과대평가된다는 문서 §7의 지적이 그대로 적용된다.

**Tandem의 나머지 부분은 견고하다** (아래 §3-15 참조): 2T 직렬 결합, interlayer 횡전도 평면(Phase B), 수직 접촉 R이 모두 구현되어 있다.

### 체크 6. §5.1 / §5.2 다중 파라미터 sweep + roadmap 출력 — **부분구현 (상)**

> **v28.45 → v28.53 변경으로 판정이 상향된 유일한 항목.** v28.50에서 edge margin이 스윕 축으로 추가되며 헤드리스 스윕이 일반화되었다.

**헤드리스 경로 — 실질 기능은 여기에 있다**

`front_electrode/optimizer.py:124-180` `optimize_grid()`는 **7축 Cartesian 스윕**이다 (151-153행):

```
finger_width × finger_pitch × busbar_number × busbar_width
              × rho_bulk × rho_contact × edge_margin
```

- 각 축이 리스트이며, `rho_*_list`의 `None` 항목은 override 없음 → 기본 상태 비트 동일 보장 (135-136행)
- `edge_margins_mm`로 마진도 축이 된다 (v28.50, 140-141행)
- **해석 가드가 설계에 들어가 있다**: 마진은 설계 자유도가 아니라 공정 제약이므로 전역 argmax를 취하면 항상 최소 마진이 뽑혀 무의미하다 — 그래서 `best` 대신 **`best_by_edge`(마진별 최적)** 를 제공한다 (143-147행, 173-179행). "어떤 마진을 고를까"가 아니라 "이 마진의 대가가 얼마인가"로 질문을 바꾼 것으로, Griddler에는 없는 개선이다.

드라이버(`scripts/optimize_m10.py`)가 장기 실행 안전장치를 담당한다: 조합별 CSV append + flush, `--resume`, `multiprocessing` spawn 병렬(워커별 독립 엔진), 스케줄링 무관 재현성을 위한 사후 정렬. 문서 §5.2의 parallel FOR에 대응한다.

**GUI 경로 — 여전히 약함**
- `_tab_sweep` (11722-11791): `rho_bulk` **1D 12점 하드코딩** (11734). 다른 파라미터 선택 불가.
- `_tab_contour` (11798-): `rho_bulk × rho_c` 2D. 단 속도를 위해 sweep 중 **Phase B와 bifacial을 강제 OFF** 한다 (11818-11828). 지도의 *형상*은 보존되나 절대값 해석 시 주의가 필요하고, 이 사실이 GUI 화면에 표시되지 않는다.

**아직 빠진 것**
- 축을 코드 밖에서 지정하는 **설정 파일(JSON/YAML)** 없음 — 축 리스트가 호출부 인자로 전달되므로 새 조합마다 드라이버 수정이 필요
- 파생 파라미터 표현식(Griddler `EVAL<>`) 대응 없음
- baseline 대비 roadmap 형태의 **4-panel(Jsc/Voc/FF/Eff)** 출력 없음. CSV에는 `engine_raw` 경유로 원자료가 대부분 들어간다

## 3. Pri A 항목별 상세 (체크리스트 외)

### 3-1. Wafer Length / Width — 완전구현
`CellGeometry.__init__(cell_w, cell_h, ..., wafer_shape, chamfer_mm)` (1184 이하). square / pseudo_square / circular 3종 모두 면적(`wafer_area()` 1250)과 외곽 폴리곤에 반영. M10 182 mm는 `scripts/optimize_m10.py`에서 상시 사용.

**주의 (경계 사례)**: `losses()`는 분모로 `self.geo.area` = W×H bounding rect를 쓰고 (6906), `shading_fraction()`은 `wafer_area()`를 쓴다 (1287-1308). square에서는 동일하나 **pseudo_square / circular에서는 두 면적 규약이 어긋난다**. 소스도 이 불일치를 주석으로 인지하고 있다.

### 3-2. No of BB / BB width / Solder-Probe Points — 완전구현
- BB 개수·폭: `GridDesign` (913, 945-999), 균등 배치 `compute_positions` (1032)
- Probe points: `n_probe_points > 0`이면 **모든 busbar에** N개 균등 배치 (1078) — Griddler 규약과 일치
- 소비 확인: terminals → `classify_nodes`의 `is_pad` (2216 이하) → 솔버 경계조건
- 회귀 이력: `n_probe_points=0` 레거시 경로가 GUI preview에서 조용히 잘못된 값(FF 30.9 / eff 8.85%)을 내던 버그를 v28.43에서 수정

### 3-4. Fingers Definition — 부분구현

구현된 것
- `n_fingers` 모드와 `finger_spacing` 모드 이중 입력. 실현 pitch 보고 `derive_n_fingers`(1001) / `get_finger_pitch_mm` — v28.18에서 W/H 축 혼동 수정
- finger 폭이 FEM 저항·접촉·발전에 케이스 단위로 배선됨 (3928-3946)

**빠진 것 — Taper가 물리에 도달하지 않는다**

`taper_factor` / `taper_dist_mm`의 전체 참조 지점은 3곳뿐이다:

| 위치 | 역할 |
|---|---|
| 955-973 | 저장 및 `tapered_h` 기본값 자동 적용 |
| 1321-1350 | `metal_rects_front()` — 3분할 사각형 생성 |
| 1390-1411 | `metal_rects_front_split()` — DESIGN 탭 표시 전용 |

도달하지 **못하는** 곳:
- **금속 저항**: `assemble_K_met_1d(..., w_f=wf, w_b=wb_case, ...)` (호출 3928, 정의 2576)는 **스칼라 폭 1개**만 받는다. BB 근처를 넓혀 저항을 낮추는 것이 taper의 본래 목적인데, 그 효과가 모델에 없다.
- **shading 보고값**: `shading_fraction()`은 `A_f = n_f · w_f_opt · fg_len` (1295)로 균일 폭을 가정 → 확장부 면적을 누락해 **shading을 과소 보고**한다.

도달하는 곳: `metal_rects_front()`를 경유하는 `compute_metal_frac` (2374) → `illum_frac`(3619, 3968), `Gc`(3934), `J01_metal` 가중(6985). 즉 **접촉·재결합·공간 발전에는 반영되나 저항과 보고 shading에는 반영되지 않는 비대칭 상태**다.

### 3-7. Mesh Detail — 부분구현

구현된 것
- 접선/수직 밀도를 **각각 별도 레벨로 지정** 가능: `generate_mesh(..., mesh_tangent, mesh_perp)` (2039, 2050)
- 금속 폭 방향·전이 영역·교차부 세분화를 레벨에서 파생 (2074 이하)
- 노드 수 목표 기반 자동 튜닝 `_generate_mesh_for_target` (2161) — 셀 크기별 국소 지수 추정. M10에서 +23% 빗나가던 문제를 v28.17에서 수정

**정의 차이 (주의 필요)**
Griddler는 밀도를 **금속 방향 기준**(접선/수직)으로 정의하나, 코드는 **좌표축 기준**이다:
- finger (x 방향 금속): 축을 따라 `x_segments`(=tangent), 폭을 가로질러 `across_y_segments`(=perp) — 2094 이하 → **일치**
- busbar (y 방향 금속): 축을 따라 `y_segments`(=**perp** 레벨), 폭을 가로질러 `across_x_segments`(=**tangent** 레벨) — 2074, 2115 → **역할이 뒤바뀜**

즉 `mesh_tangent`를 올리면 finger에는 접선 방향으로, busbar에는 수직 방향으로 작용한다. H-pattern에서는 두 레벨을 같게 두는 것이 보통이라 실사용 영향은 작지만, Griddler와 설정을 맞춰 대조 검증할 때는 이 매핑을 반드시 감안해야 한다.

4-노드 가이드라인 자동 검사는 없음 (체크 4 참조).

### 3-8. Metallization sheet resistance — 완전구현

| 층 | 파라미터 | 소비 지점 |
|---|---|---|
| front 금속 (finger/busbar) | `rho_bulk`, `finger_h`, `shape_cf` (`GridDesign` 913 이하) | `assemble_K_met_1d` (2576) |
| front 반도체/TCO | `Rs_sheet` | `assemble_K` (2437) → `Pe` (6852) |
| rear TCO/emitter | `Rs_rear_tco` (1574) | `_Kr` |
| rear 금속 | `Rs_rear_metal_sheet` (1589) | `_Krm` |
| interlayer 횡전도 | `Rs_junction` (1607) | `_K_junc` (3979) |

문서 §2.7의 변환식 `ρ_sheet = ρ_bulk / t`가 소스에 명시되어 있고, 과거 µΩ·cm를 Ω/sq로 오기입해 1000배 틀렸던 이력까지 주석에 남아 있다 (1589 부근). `Rs_junction` 기본 5000 Ω/sq가 PRO의 10k∥10k에 대응한다는 근거도 기록됨 (1607 이하).

### 3-9. Wafer internal series R / shunt conductance — 완전구현
- **직렬**: `Rs_vert_top` / `Rs_vert_bot` (1508-1516), 기본 0. 터미널 IR drop으로 적용: `V_terminal = V_solver − J·Rs_vert_total` (6370-6378). 구명칭 4종은 property 별칭으로 하위호환
- **shunt**: `Rsh_top`(1505) / `Rsh_bot` / `Rsh_single`. 노드별 `V_diode²/Rsh · nodal_area` 로 손실 계상 (6920 이하)
- interlayer 수직 접촉 R `Rc_junction`은 위 둘과 명확히 구분됨 (1508-1516 주석)

**참고**: Griddler PRO의 *External* series resistance(모듈 케이블·인터커넥션, Pri B)는 별도 항목이 없다. 현재는 `Rs_vert`에 수동 합산하는 수밖에 없고, 그러면 "셀 내부"와 "모듈 배선"이 한 값에 섞인다.

### 3-11. Power loss bar graph — 완전구현

`FESTSolver.losses()` (6822-7041)가 mW/cm² 단위로 전 채널을 반환한다:

| 채널 | 산식 | 라인 |
|---|---|---|
| `Pe` (emitter/TCO) | `V·Ke·V` 이차형식 | 6852 |
| `Pf_finger` / `Pf_busbar` | 1D 금속망 **엣지별** `g_ij·ΔV²`, 양 끝점 플래그로 분류 | 6871-6884 |

## 6. 권고 우선순위

1. **`extraction_method` 처리** — 솔버에 연결하거나, 그때까지 GUI에서 비활성화 + "미구현" 표기. 지금은 사용자가 틀린 결과를 옳다고 믿을 수 있는 상태다. (비용 小 / 위험 大)
2. **Taper를 저항과 shading에 연결** — `assemble_K_met_1d`(2576)에 구간별 폭을 넘기고, `shading_fraction`(1287)이 `metal_rects_front()`를 적분하도록 통일. 현재는 taper를 켜면 저항 이득 없이 재결합 손실만 늘어 **taper가 항상 불리하게 나온다**. (비용 中 / 물리 정확도 直結)
3. **Tandem non-overlapping area Jsc** — 실험 셀 형상에 직결되며 현재는 Jsc가 계통적으로 과대평가된다. (비용 中)
4. **Mesh 4-노드 판정기 추가** — `mesh_quality_metrics`(1786)에 두 지표 추가. 기존 수렴성 이슈 재점검에 즉시 활용 가능. (비용 小 / 진단 가치 大)
5. **§5.1 roadmap 출력만 얹기** — 스윕 엔진(`optimize_grid`, 7축 + `best_by_edge`)은 이미 충분하다. 남은 것은 (a) 축 정의를 설정 파일로 빼내기, (b) baseline 대비 시나리오 표현, (c) **Jsc/Voc/FF/Eff 4-panel** 출력. 논문 figure에 직결된다. (비용 中→小)

Print method(dual print)와 FF drops waterfall 6단계 러너는 Griddler 대조 검증을 본격화할 때 착수하는 것이 순서상 맞다고 본다.
