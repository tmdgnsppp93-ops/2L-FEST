# 공간 분포 입력 인터페이스 구현 계획 (1단계: txt/csv)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용자가 txt/csv 2D 행렬 파일로 비균일 공간 분포를 넣을 수 있게 한다. 파일 로더 + GUI까지가 1단계다. 이미지(jpg/tif/bmp) 지원은 **2단계로 분리**한다.

**Architecture:** 엔진은 이미 완성되어 있다. `SpatialMap`(`2L_FEST.py:3248`)이 노드 좌표에서 배율 배열을 만들고, `_spatial_mult`(`2L_FEST.py:3838`)를 거쳐 접촉 컨덕턴스·J01/J02/광생성에 곱해진다. **없는 것은 사용자가 맵 객체를 만들 방법 하나뿐이다** — 저장소 전체에서 `SpatialMap(`을 생성하는 코드는 `_audit.py:135-145`(스모크 스크립트)뿐이고 앱 코드에는 0건이다(2026-08-17 재확인). 따라서 이 작업은 **입력 경로(I/O + GUI) 추가**이며 물리 경로는 건드리지 않는다.

**Tech Stack:** Python ≥3.10, numpy/scipy/customtkinter (모두 기존 의존성). **1단계에서 신규 의존성 없음.**

**Spec:** 별도 스펙 문서 없음 — 설계 결정이 적어 이 계획서 §설계 결정에 흡수했다.

## 메시 노드로의 보간 방식

**이미 구현되어 있고, 바꾸지 않는다.** `SpatialMap.evaluate()`의 `csv` 분기(`2L_FEST.py:3310-3322`):

```
y_axis = np.linspace(0.0, H_cm, ny_)        # 행 방향
x_axis = np.linspace(0.0, W_cm, nx_)        # 열 방향
RegularGridInterpolator((y_axis, x_axis), matrix,
                        bounds_error=False, fill_value=None)
result = interp(column_stack((clip(y,0,H), clip(x,0,W))))
```

- **쌍선형(bilinear) 보간.** `RegularGridInterpolator`의 기본 `method='linear'`.
- **격자 정렬은 꼭짓점 기준(vertex-aligned)이다.** `linspace(0, H, ny)`이므로 `matrix[0]`은 `y=0`(셀 경계), `matrix[-1]`은 `y=H`(반대편 경계)에 놓인다. **픽셀 중심(cell-centered) 규약이 아니다.**
- 노드 좌표를 `[0,W]×[0,H]`로 **clip한 뒤** 조회하므로, `fill_value=None`(외삽 허용) 설정에도 불구하고 **외삽은 실제로 발생하지 않는다.** 셀 경계 밖 노드는 경계값을 받는다.
- 행렬은 **최소 2×2**여야 한다(`3311-3313`). 1×N·N×1·스칼라는 `ValueError`.
- 결과는 노드 길이 `N` 배열이며 `self.pts`(노드 좌표, cm)에서 평가된다(`_spatial_mult` `3851`).

> ⚠ **이 격자 정렬 규약이 교차검증의 핵심 위험이다.** Griddler가 같은 행렬을 **픽셀 중심**으로 해석하면 맵 전체가 반 칸씩 어긋난다. 행렬이 작을수록(예: 4×4) 오차가 커진다. §미해결 1 참조.

## 맵 미지정 시 비트 동일이 보장되는 근거

**두 겹으로 보장된다. 둘 다 "값이 1인 곱셈"이 아니라 "곱셈을 아예 하지 않음"에 기대고 있다.**

**(1) 기본값이 `None`이고, `None`이면 곱셈 자체가 실행되지 않는다.**

`dp.spatial_*`의 클래스 기본값은 `None`이다(`2L_FEST.py:1704-1707`). `_spatial_mult`는 spec이 `None`이면 배열을 만들지 않고 **`None`을 반환한다**(`3844-3846`, 주석: *"caller treats None as all-ones (skips the multiply)"*). 소비 지점 전부가 `if ... is not None:` 가드 안에 있다:

| 위치 | 대상 | 가드 |
|---|---|---|
| `2L_FEST.py:4028-4030` | `_Gc` (접촉 컨덕턴스) | `if _m_rc is not None:` |
| `2L_FEST.py:4368-4374` | J01/J02 top | `if _m_j01 is not None:` / `if _m_j02 is not None:` |
| `2L_FEST.py:5867-5869` | 단일셀 경로 | 동일 패턴 |
| `2L_FEST.py:6153-6155` | 보고/손실 경로 | 동일 패턴 |

→ 맵이 없으면 **부동소수점 연산이 하나도 추가되지 않는다.** 이것이 1차 근거다.

**(2) 예외적으로 곱셈이 실행되는 bottom-cell 경로는 리터럴 `1.0` 곱이다.**

```python
_J01b = dp.J01_bot * (_m_j01 if _m_j01 is not None else 1.0)   # 2L_FEST.py:4378 부근
```

여기는 가드 대신 `1.0`을 곱한다. **IEEE 754에서 `x * 1.0 == x`가 정확히 성립**하므로 비트 동일이 산술로 보장된다. Metal Optical Transparency 작업의 `optical_widths()`가 곱셈만 쓴 것과 **같은 근거**다(`docs/WORKLOG.md` §2-3).

> ⚠ **이 성질에 기대므로, 로더·GUI가 "맵 없음"을 `None`이 아닌 `SpatialMap(mode='uniform')`으로 표현하면 안 된다.** uniform 맵은 `np.full(N, 1.0)` 배열을 만들어 실제 곱셈을 실행시킨다. 값은 같겠지만 **가드를 우회하므로 위 (1)의 근거가 사라진다.** 맵 해제는 반드시 `dp.spatial_x = None`이어야 한다. 이건 단위 4에서 테스트로 고정한다.

**(3) 맵을 붙일 대상 인스턴스 주의.** `spatial_*`는 클래스 속성이므로, GUI가 전역 `DP`(`2L_FEST.py:7201`)에 맵을 붙여도 `solve()` 내부 폴백 `dp = DiodeParams()`(`4272`, `5828`, `6145`, `6203`, `6342`, `6452`, `6919`, `7159`)로 만들어진 인스턴스는 맵을 못 본다. **반대로 `DiodeParams.spatial_j01 = ...`처럼 클래스에 직접 붙이면 모든 인스턴스에 전역 누출된다.** 로더/GUI는 항상 **`solve()`에 실제로 전달되는 dp 인스턴스**에만 붙인다.

### 단위 1 — 캐시 무효화를 내용 기반 해시로 정정

**단위 2 이전에 반드시 해야 한다.** 지금 빌드 캐시는 맵의 **`id()`**로 변경을 감지한다(`2L_FEST.py:3897-3901`, 주석도 *"cheap id()-based tag"*라고 인정):

```python
_sm_tag = (id(dp.spatial_j01) if ... else 0, ...)
h = (rm, hf, ..., _sm_tag)
if self._cache_hash == h: return        # 3902-3904
```

`_spatial_cache`도 `(id(dp), which, id(spec))`을 키로 쓴다(`3847`).

- 지금까지는 안전했다. 앱 코드에 `SpatialMap(` 생성이 0건이라 맵이 생성·소멸된 적이 없기 때문이다.
- **GUI 로더가 생기는 순간 전제가 깨진다.** 맵 A 로드 → 실행 → 맵 B 로드(A는 참조 해제) → CPython이 해제된 A의 주소를 같은 크기의 B에 재사용하면 `_sm_tag`가 변하지 않는다 → `_cache_hash`가 일치 → **`_Gc`가 재빌드되지 않고 A의 결과가 조용히 재사용된다.** 오류도 경고도 없다.
- 조치: `id()` → **내용 기반 해시**(mode + 스칼라 파라미터 + `matrix.tobytes()`). `SpatialMap.content_key()` 같은 메서드 하나로 모으고 `_sm_tag`·`_spatial_cache` 키 양쪽에서 쓴다.

**회귀 영향 범위:** `_build`의 캐시 적중 판정 경로. 맵이 `None`이면 태그가 `(0,0,0,0)`으로 지금과 동일해야 하고, 그 경우 **캐시 거동·결과 모두 불변**이어야 한다. 물리식 무변경. 성능: 맵이 있을 때만 `tobytes()` 해시 비용이 추가되며, `_build` 호출당 1회다.

> 이 단위를 단위 2·4보다 먼저 두는 이유: 나중에 하면 "GUI가 가끔 옛 결과를 준다"는 재현 어려운 버그를 먼저 만나게 된다.

## 미해결 — 단위 3에서 판정할 것

> 남은 2건은 **모두 단위 3(Griddler 대조)에서 처리한다.** 착수 전에 미리 정리할 필요 없다.

**1. 격자 정렬 규약이 Griddler와 같은가?** 2L-FEST는 꼭짓점 정렬이다(`linspace(0,H,ny)` → `matrix[0]`이 `y=0` 경계). Griddler가 픽셀 중심이면 맵이 반 칸 어긋나고, 행렬이 작을수록 오차가 커진다. **교차검증 결과를 발표·보고에 쓰기 전에 반드시 확정할 것.**

**2. 행 방향(상하)이 같은가?** `matrix[0]`이 2L-FEST에서는 `y=0`이다. 텍스트 파일의 첫 줄은 사람 눈에 보통 **위쪽** 행이다. Griddler가 첫 줄을 위(y=H)로 읽으면 **맵이 상하 반전된다.** 대칭 행렬로 시험하면 이 오류가 드러나지 않으므로 단위 3의 시험 행렬은 **반드시 비대칭**이어야 한다.

**3. ~~이 4종 물성 외에 박사님이 원하는 대상이 있는가?~~** — ✅ **종결 (2026-08-17): `j01`/`j02`/`gen`/`rc` 4종으로 확정.**

> 면저항(`Rs`) 공간 분포는 **주입 지점이 강성행렬 조립 단계라 성격이 다르고**(4종은 조립이 끝난 뒤 노드별 배율을 곱하는 구조다), **박사님 지시에도 포함되지 않았다.** 필요해지면 이 계획의 확장이 아니라 **별도 항목으로 신설**한다 — 그때는 **물리 변경 있음**으로 분류되어 §1-2 머신 분담(원 캡처 PC 핀 확인)이 적용된다.
