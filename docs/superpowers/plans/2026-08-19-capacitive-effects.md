## 0. 범위 판정 — 무엇을 따라가고 무엇을 하지 않는가

### 따라간다: Griddler PRO가 구현한 것

**기준은 Griddler PRO다.** 이 저장소의 기능 범위 판단은 일관되게 그렇게 해 왔다
(`docs/pro_feature_map_2026-08-14.md`, `docs/griddler_feature_map.md`).

### 하지 않는다: 페로브스카이트 이온 이동 히스테리시스

**PRO에 없는 물리다.** 그러므로 이 계획의 범위 밖이다.

근거와 구분을 분명히 해 둔다 — 둘 다 "I-V 히스테리시스"로 나타나지만 **다른
현상**이다.

| | 용량성 과도 (이 계획) | 이온 이동 히스테리시스 (범위 밖) |
|---|---|---|
| 원인 | 접합·확산 용량의 전하 충방전 | 페로브스카이트 층 내 이동성 이온의 재분포 |
| 시간 상수 | µs ~ ms | s ~ 수백 s |
| 모델 | 집중정수 C, 소자 물리로 유도 가능 | 이온 드리프트-확산 + 계면 축적. 별도 수송 방정식 |
| PRO | **있다** (§6.6) | 없다 |

**둘을 섞으면 안 되는 실질적 이유**: 시간 상수가 3~6 자리 다르다. 같은 시간
적분기로 다루면 이온 쪽이 강성(stiff)을 지배해 스텝이 잘게 쪼개지고, 용량성 효과의
검증이 이온 모델의 정확도에 묶인다. 용량성만 먼저 넣으면 **PRO와 대조 가능한
범위**에 머무를 수 있다.

> 이것을 맨 앞에 적는 이유: 2L-FEST는 PST(perovskite-Si tandem) 도구이므로
> "히스테리시스"라는 말이 나오면 이온 쪽을 기대하는 것이 자연스럽다. 이 계획이
> 그것을 **하지 않는다**는 것을 나중에 읽는 사람이 처음 세 줄에서 알아야 한다.

### ⚠ 사용자 경고에 대한 답 — §6.6은 계산기인가 솔버인가

**질문 자체가 옳았고, 답은 "둘 다 아니다"에 가깝다.**

| | 근거 |
|---|---|
| **인터페이스는 솔버 쪽이다** | §6.6은 *"in the **simulation screen** use either of these commands"* 라고 적는다. 시뮬레이션 페이지 = FEM 솔버 페이지다 |
| **모델은 공개되어 있지 않다** | §6.6에 수식이 없다. 무엇이 시간 항을 만드는지 매뉴얼이 말하지 않는다 |

| **두 절이 지목하는 물리량이 같다** | §6.6 = *"high lifetime → ms 정상상태 도달"*, §6.2 = `1/τ* = 1/τ + iω`. **둘 다 벌크 수명 τ다** |

**따라서 Appendix A.5 오독의 재발은 없다** — 이번에는 부록의 기호를 솔버 모델로
읽은 것이 아니라, **부록이 계산기의 것임을 부록 제목으로 확인**하고 그 사실을
판정에 썼다. 다만 결론의 방향은 base lateral 때와 **반대**다: 그때는 *"부록은
계산기 것이니 솔버 모델의 근거로 쓰지 말자"* 였고, 이번에는 *"매뉴얼이 시간
의존성을 다루는 방식 자체가 계산기 쪽이므로, **솔버에 용량을 넣는 설계는 PRO를
따라가는 것이 아니다**"* 이다.

### [지시] §6.6 (p.90) "Simulating transient solar cell characteristics"

- 절 제목과 위치: §6.6, p.90
- 관련 명령어: `SETSWEEPRATE`, `SETSWEEPTIMING`

여기서 읽을 수 있는 것은 **인터페이스의 형태**다. 명령어가 둘로 갈린다는 것은

- `SETSWEEPRATE` — 스윕 **속도** (dV/dt)
- `SETSWEEPTIMING` — 스윕 **타이밍** (구간별 시간 배분 / 정착 시간 / 방향 전환?)

즉 PRO는 "속도 하나"가 아니라 **시간 프로파일**을 받는다. 우리 인터페이스도
속도 스칼라 하나로 끝내면 안 된다는 신호다.

> ⚠ **`SETSWEEPTIMING`의 정확한 의미는 확정되지 않았다.** 위 괄호는 추측이며
> 계획의 근거로 쓰지 않는다. 단위 0에서 매뉴얼 원문을 확인해 이 표를 채운다.

### 기술되지 않은 것 (또는 우리가 모르는 것)

**수식이 공개되어 있는지 자체를 확인하지 못했다.** 그러므로 다음은 전부 미확정이다.

- 용량 모델의 형태 (접합 용량만? 확산 용량 포함? 노드별? 집중정수?)
- 시간 적분 방식 (음함수/양함수, 차수)
- 파라미터화 (C를 직접 입력? 도핑·수명에서 유도?)
- 후면/interlayer 용량 취급

### 판단: 자체 유도로 간다 — 단, 유도임을 명시하고

매뉴얼 수식이 확인되지 않았으므로 **표준 소자 물리로 유도한다** — 접합 용량 `C_j`
+ 확산 용량 `C_d`.

이 저장소의 기존 관행과 같다: `J01_coupling`(LC 항, `2L_FEST.py:1974-1982`)도
*"the standard one"* 이라는 근거로 채택하고 출처(Zeder 2025 · Jäger 2021)를 주석에
남겼다.

**단, 규약과 확인을 구분한다.** `docs/spatial_map_convention.md`가 세운 원칙을
그대로 적용한다:

> 규약은 **선언**이지 **확인**이 아니다 — Griddler와 같은 입력이 같은 결과를 준다는
> 주장은 하지 않는다.

⚠ **base lateral의 오독을 반복하지 않기 위한 절차**를 못 박는다.

그 작업의 초안은 매뉴얼 **Appendix A.5**의 `Rs,base`를 근거로 삼았는데, 그것은
Ω·cm² 집중정수여서 우리의 `Rs_vert_bot` 층위였다. **부록의 기호를 본문의 모델로
읽은 것**이 오독의 원인이었다.

| 규칙 | 내용 |

## 2. 토폴로지 판정 — 새 미지수인가 기존 항인가

**이것을 먼저 판정한다.** base lateral에서 이 판정 하나로 "7분기 수술"이 **0곳**이
됐다(v28.59). 초안이 6번째 전도 평면을 신설하려 했으나, β 토폴로지로 정리되면서
`1/Rs_eff = 1/Rs_rear_tco + 1/Rs_base` 한 줄이 됐고 `assemble_K`가 `1/Rs`에
선형이라 **미지 벡터가 불변**이었다.

### [repo] 코드로 확인한 구조

잔차는 각 노드의 KCL이다. 예: `_solve_tandem_junction`

```
F[oVe:oVe+N] = self._Ke @ Ve - It          # It = Jt * self._na
```

야코비안은 **정적 블록 복사 + 다이오드 대각 추가**다. 5개 분기 전부 같은 패턴이다
(`2L_FEST.py:5064` `:5209` `:6477` `:6620` `:6746`):

```
J = self._J_static_tandem.copy()   # 선형 FEM 블록만 — Ke / Gc / Km / Kr
...                                # dJt 대각을 더한다 (이미 노드 길이 배열)
```

정적 야코비안(`:4801` `:4859` `:4888` `:4944`)에는 **다이오드 항이 없다.**

### [유도] 판정: 음함수 차분이면 새 미지수가 없다

용량 항은 노드 전류에 `C · dV/dt`를 더한다. 후향 오일러(음함수)로 이산화하면

```
C/Δt · (V − V_prev)
```

- 잔차에 상수항 `− C/Δt · V_prev`
- 야코비안 **대각에 `+ C/Δt`**

**즉 기존 잔차의 추가 항이고 대각 기여다. 새 평면도 새 미지수도 없다.**
`dJt`가 이미 대각에 더해지는 것과 **구조적으로 동일**하다. 미지 벡터 레이아웃·
오프셋 식·희소성 패턴이 전부 불변이다.

> base lateral과 같은 결론이지만 **이유가 다르다.** 그쪽은 `assemble_K`가 `1/Rs`에
> 선형이라는 대수적 성질이었고, 이쪽은 **시간 이산화 방식의 선택**이 만든 성질이다.

### ⚠ 이 판정은 조건부다

**양함수(explicit) 차분을 쓰면 성립하지 않는다** — `V_prev`만으로 `V`를 직접
계산하게 되어 뉴턴 루프 자체의 역할이 바뀐다. 그리고 용량이 작으면 시간 상수가
작아 양함수는 스텝 제한이 심하다(강성).

**따라서 §3의 시간 적분 방식 확정이 이 판정의 전제다.** 순서를 바꾸면 안 된다.

### 단위 0에서 코드로 검증할 것

판정을 글로 남기는 것으로 끝내지 않는다. base lateral 단위 0이 `spsolve`를
가로채 `Ns`를 관측한 것과 같은 방식으로:

- `C = 0`(off)에서 **미지 벡터 길이가 v28.61과 동일**함을 6개 분기 전부에서 고정
- 희소성 패턴(`J.nnz`, `J.indptr`)이 불변임을 고정
- → `tests/test_base_lateral.py`의 `BRANCH_CASES`를 **import해서** 쓴다(복제 금지).
  v28.61 시점 그 표는 `_solve_single_bifacial`까지 포함해 **6분기 전부**를 덮는다

## 3. 시간 적분 방식과 스윕 루프 구조

### [유도] 시간 적분

**후향 오일러(1차 음함수)로 시작한다.** 근거:

1. §2의 토폴로지 판정이 성립한다 (대각 기여만)
2. 무조건 안정 — 용량 시간 상수가 작아도 스텝이 강제로 쪼개지지 않는다
3. 기존 뉴턴 루프에 그대로 얹힌다. 각 시간 스텝이 **지금과 같은 정상상태 풀이 한
   번**이고, 잔차·야코비안에 항 하나가 늘어날 뿐이다

2차(BDF2 / Crank-Nicolson)는 **하지 않는다** — 정확도가 필요하다는 근거가 아직
없고, 시작값 문제와 진동을 함께 들여온다. 단위를 나눠 두고 필요해지면 그때.

### ⚠ 진짜 구조 변경은 잔차가 아니라 `calc_iv`다

`docs/WORKLOG.md`는 *"스윕 루프 구조 자체가 바뀐다"* 고 적었다. **더 정확히
말하면 `calc_iv`(`2L_FEST.py:7154`)는 스윕이 아니다.** 코드로 확인한, 이력 의존과
양립 불가한 요소가 **네 개** 있다.

| # | 요소 | 위치 | 왜 충돌하나 |
|---|---|---|---|
| 1 | `eval_cache` (전압 키) | `:7184-7198`, `_CKEY_DIGITS = 10` | 같은 `Vb`가 정·역 스캔에서 **다른 해**를 갖는다. 전압 키 캐시는 무효다 |
| 2 | `vals[::-1]` 고→저 순서 | `:7208` | **수렴 편의**를 위한 순서다. 물리적 스캔 방향이 아니다 — `SETSWEEPRATE`에서는 방향·속도가 **물리**다 |
| 3 | `_bisect_root` | `:7213` | Voc/MPP 근찾기가 전압을 **비단조로 왕복**한다. 시간 순서가 없다 |
| 4 | MPP 적응 리파인먼트 | `npts=14` + fine 10 | 점을 **나중에 삽입**한다. 시간 순서 스윕에서는 불가능하다 |

### 판단: 기존 경로를 고치지 말고 **별도 경로**를 둔다

```
calc_iv(...)              ← 정상상태. 그대로 둔다. 비트 보존 대상
calc_iv_transient(...)    ← 신설. 시간 순서 스윕
```

이유 두 가지.

1. **비트 보존.** 기존 경로를 건드리면 정상상태 결과가 움직일 위험이 생긴다.
   이 저장소의 검증 조건은 항상 "기존 설정에서 결과 불변"이고 그 판정을 비트 핀이
   한다. 손대지 않으면 그 위험이 0이다.
2. **의미가 다르다.** 정상상태 I-V는 "각 전압에서의 평형점 집합"이고, 과도 I-V는
   "한 번의 시간 궤적"이다. 후자에서 MPP 적응 리파인먼트나 이분법 근찾기는 정의
   자체가 없다. 같은 함수에 둘을 넣으면 `if transient:` 분기가 함수 전체에
   흩어진다 — **우선순위 0 결함이 정확히 그렇게 생겼다.**

> 신설 경로는 `_eval_internal`/`_bisect_root` 같은 내부 헬퍼를 **재사용하지
> 않는다.** 재사용하려는 유혹이 1·3번 항목을 되살린다.

### 신설 경로가 받는 것

[지시] `SETSWEEPRATE` / `SETSWEEPTIMING`이 둘로 갈린다는 사실에 맞춘다.

- 스캔 방향과 시작·끝 전압
- dV/dt (또는 구간별 시간 프로파일)
- 정착 시간 / 시간 스텝 정책

⚠ 구체적 시그니처는 **단위 0에서 매뉴얼 §6.6을 확인한 뒤** 확정한다. 지금
정하면 R4를 위반한다.

## 4. warm-start · 캐시 무효화 설계

**이 절이 이 작업의 가장 위험한 부분이다.**

### [repo] 지금의 구조

```
_cache_hash (:4582)
  h = (rm, hf, wf, wb_case, rc, rc_rear, Rs_front, cf,
       Rs_rear_metal_auto, Rs_rear_tco, Rs_j, _base_tag, _sm_tag)
```

**`Vb`가 없다.** `Vb`만 바뀌면 `_build`가 조기 반환하고(`:4583`) warm-start 벡터가
**보존된다**. `h`가 바뀌면 warm 벡터 전부 무효화(`:4587-4592`).

warm 벡터: `_warm_V_bf` · `_warm_V_tf` · `_warm_V_sbf` · `_warm_V_junc_bf`(v28.28,
`:5698` `:5982`) · `_warm_V_sf`, 그리고 `_warm_Vb_ref`(`:4284`).

### ⚠ 함정: 같은 배열이 두 가지 역할을 하게 된다

| | 지금 | 과도 해석에서 |
|---|---|---|
| 역할 | **순수 최적화** — 시작 추정값 | **방정식의 일부** (`V_prev`) |
| 오염되면 | 느려질 뿐. 해는 같다 | **답이 틀린다.** 오류도 경고도 없이 |

**이 둘을 같은 슬롯에 두면 안 된다.** `_warm_V_*`를 `V_prev`로 재사용하는 것이
가장 짧은 구현이고 가장 위험한 구현이다.

### 설계안

**시간 상태를 warm-start와 분리한 전용 슬롯에 둔다.**

```
self._transient_state = None   # (t, V_prev, dt_prev, scan_dir) 또는 None
```

규약 세 가지.

| # | 규약 | 이유 |
|---|---|---|
| T1 | `None`이면 **정상상태**다. 과도 항을 아예 계산하지 않는다 | 무맵 경로 비트 동일의 근거와 같은 형태 — *"0을 더한다"* 가 아니라 *"항을 만들지 않는다"* (`clear_spatial_map` 독스트링 참조) |
| T2 | `_build`의 조기 반환이 이 슬롯을 **건드리지 않는다** | `Vb`만 바뀔 때 warm-start가 보존되는 것과 같은 이유. 시간 스텝마다 `Vb`가 바뀐다 |
| T3 | `_cache_hash`가 바뀌면 **반드시 무효화**한다 | 지오메트리·재료가 바뀐 뒤의 `V_prev`는 다른 셀의 해다. 조용히 쓰면 답이 틀린다 |

### 해시 슬롯

과도 파라미터(C_j, C_d, sweep rate, dt 정책)를 `h`에 추가한다. **`_base_tag`와
`_sm_tag`의 "꺼져 있으면 상수 0" 규약을 그대로 따른다** — off에서 해시가 안 움직여야
비트 동일 근거가 선다(v28.60 `:4576-4581`의 판단).

`tests/test_base_lateral.py`에 이 패턴의 선례가 있다: `Rs_base`가 해시 튜플에서
**정확히 한 슬롯만** 건드리고 off일 때 그 슬롯이 상수임을 고정하는 테스트들
(`:633-730`, 슬롯 번호를 실측으로 찾는 것까지). **같은 테스트를 과도
파라미터에도 만든다.**

### [repo] `_mesh_seed_snapshots`는 bias→해 사전이다

```
self._mesh_seed_snapshots[float(voltage_bias)] = snapshot     (:4377)
```

**bias를 키로 쓴다.** 이력 의존에서는 한 bias에 해가 여러 개(정·역 스캔, 다른
시각)이므로 이 사전이 **모호해진다.**

판단: **과도 경로에서는 mesh prolongation seed를 비활성화한다.** 키를
`(bias, t, dir)`로 넓히는 것은 가능하지만, 그 seed는 순수 최적화(더 거친 메시의
해를 보간해 시작값으로 쓰는 것)이므로 **끄면 느려질 뿐 답은 같다.** 위험 대비
이득이 맞지 않는다. 정상상태 경로는 그대로 둔다.

## 5. dV/dt → 0 극한에서 비트 동일

**검증 조건: 과도 off에서 기존과 비트 동일.** → 핀 스택 머신 필수
(§`docs/WORKLOG.md` §1-2 — KIST PC 또는 집 데스크톱).

근거를 **두 겹**으로 세운다. 하나만으로는 부족하다는 것을 v28.59가 보여줬다.

### 근거 (1) — 구조: 항을 만들지 않는다

`_transient_state is None`이면 과도 항의 계산 자체를 건너뛴다(T1). 부동소수점 연산이
**하나도 추가되지 않는다.** `spatial_*`의 `is not None` 가드와 같은 형태다.

> `C = 0`을 넣어 `C/Δt = 0`을 더하는 방식은 **쓰지 않는다.** 값은 같지만 덧셈이
> 실행되어 이 근거가 사라진다. `clear_spatial_map`이 `SpatialMap(mode='uniform')`을
> 금지하는 것과 같은 이유다.

### 근거 (2) — 감시: 기존 비트 핀이 이미 본다

`test_default_pin`(기본 = Phase B / full_area) · `test_legacy_pin`(Phase A)이
과도 off 경로를 돈다. 물리가 움직이면 이 둘이 먼저 깨진다.

### ⚠ dV/dt → 0 극한은 비트 동일이 **아니다** — 구분할 것

과도를 **켠 채로** `dV/dt → 0`으로 보내면 정상상태 해에 **수렴**하지만 비트 동일은
아니다. `C/Δt · (V − V_prev)`가 잔차에 실제로 더해지고, 수렴점에서 그 항이 0에
가까워질 뿐이기 때문이다.

| 조건 | 기대 |
|---|---|
| 과도 **off** (`_transient_state is None`) | **비트 동일** — 근거 (1)(2) |
| 과도 **on**, dV/dt → 0 | 정상상태 해에 **수렴** (허용오차 판정) |

**두 번째를 비트 동일로 적으면 안 된다.** 그렇게 적으면 테스트가 영원히 빨간불이
되거나, 통과시키려고 허용오차를 몰래 키우게 된다. 별개 테스트로, 별개 판정
기준으로 둔다.

수렴 속도 자체도 검증 대상이다 — dV/dt를 10배 줄일 때 정상상태와의 차이가 1차로
줄어야 한다(후향 오일러). 그것이 시간 적분이 제대로 배선됐다는 증거다.

>
> 따라서 잔차에 `C·dV/dt`를 넣는 설계는 **PRO와 같은 기능을 다른 구조로**
> 구현하는 것이다. `docs/spatial_map_convention.md` §2가 세운 *"기능적 대응 ≠
> 호환"* 구분을 그대로 상속한다 — **같은 입력이 양쪽에서 같은 결과를 준다는
> 주장은 하지 않는다.**

이것은 착수를 막는 근거가 **아니다.** 저장소가 이미 같은 판단을 두 번 했다
(공간 분포 규약, `J01_coupling`의 *"the standard one"*). 다만 **문서에 그렇게
적어야 하고, 발표·보고에서 "Griddler PRO 등가"로 인용하면 안 된다.**

### (c) 결정적 사실 — 시간 의존성이 사는 층을 우리는 **구현하지 않기로 이미 정했다**

§6.2가 시간 의존성을 넣는 자리는 **base transport calculator / Appendix A**다
(`griddler_feature_map.md` §2.8-a). 그 계층은 매뉴얼에서
`J01_pass` · `J01_metal` · `J_L`을 **역산해 내는 해석식 그물**이고,

- `docs/pro_feature_map_2026-08-14.md` **#2 Cell cross-sectional model = 미구현**
- `docs/WORKLOG.md` §3 **구현 불필요 확정** — *"지시 범위 밖. J01_pass/J01_metal은
  역산이 아니라 **직접 입력**이 현 설계"*

즉 **2L-FEST는 그 층을 갖지 않기로 명시적으로 결정했다.** 그러므로

| 결론 | 내용 |
|---|---|
| **파라미터화** | 벌크 수명 τ에서 `C_d`를 유도하는 경로는 **쓸 수 없다** — τ·SRV·두께·도핑이 전부 없고(#2), 넣으면 구현 불필요 확정을 뒤집는 것이 된다. → **노드 용량을 직접 입력**받는다. `J01_pass`/`J01_metal`을 직접 입력받는 현 설계와 **같은 계층 선택**이다 |
| **한계 문구** | *"용량을 재료 물성에서 유도하지 않는다. 사용자가 직접 넣는다"* 를 §7에 추가한다 |
| **§6.2 AC 응답** | §7 "후속으로 남는 것"의 *"추가 물리 없이 도달 가능할 수 있다"* 는 **틀렸다.** PRO 방식(복소 τ)은 계산기 층을 요구하고, 우리 방식(시간 항)으로 AC를 하려면 별도의 소신호 선형화가 필요하다. **더 멀어졌다** |

### (d) 인터페이스가 단순해진다 — 입력 형태 하나로 둘 다 덮는다

`SETSWEEPTIMING`이 **(시간, 전압) 2열 표**라는 것이 확인됐으므로(§1-0 #4):

```
calc_iv_transient(..., schedule=(t_array, V_array))
```

하나면 `SETSWEEPRATE`(등속)는 **두 점짜리 표**의 특수 케이스다. §3의
*"정착 시간 / 방향 전환 / 구간별 배분"* 같은 별도 인자를 만들 필요가 없다 —
그것들은 전부 표로 표현된다. **§3 "신설 경로가 받는 것"의 3항목은 1항목으로
줄어든다.**

> 단, 시간 **스텝 정책**은 별개다. 표는 *무엇을 재현할 것인가*(물리)이고 스텝은
> *얼마나 잘게 풀 것인가*(수치)다. 둘을 한 인자에 섞지 말 것.

### (e) 대조 자료 — §6.6에는 없고 §6.2에는 있다

|---|---|
| §6.6 | **없다.** 그림 한 장(Voc = 741 mV 셀, `SETSWEEPRATE 100`의 역방향 스윕) |
| §6.2 | **있다.** p.83에 `ACSWEEP` 출력 50행 (10 Hz ~ 1 MHz) |

그때도 우리 모델이 PRO와 다른 구조이므로 (b)의 단서가 붙는다.

### (g) §2 판정의 전제가 실측으로 확인됐다 — 단위 0 특성화 결과

§2는 *"후향 오일러면 대각 기여뿐이므로 희소성 패턴이 불변"* 이라고 판정하면서
**그 판정이 조건부임**을 적었다. 실제로 조건이 하나 더 있었다:

> **대각에 값을 더하는 것이 희소성을 바꾸지 않으려면, 대각 자리가 이미
> 구조적으로 존재해야 한다.** 하나라도 비어 있으면 시간 항이 `nnz`를 늘린다.

계획서에는 그 조건이 명시돼 있지 않았다. 단위 0이 그것을 먼저 재봤다.

| 분기 | Ns | nnz | 대각 슬롯 | 판정 |
|---|---:|---:|---:|:---:|
| Phase A / full_area | 12,980 | 51,380 | 12,980 | ✅ |
| **Phase B / full_area** (기본 설정) | 16,789 | 83,447 | 16,789 | ✅ |
| Phase B / bifacial | 24,942 | 207,968 | 24,942 | ✅ |
| Phase A / bifacial | 19,483 | 119,644 | 19,483 | ✅ |
| 단일셀 / full_area | 9,171 | 39,953 | 9,171 | ✅ |
| 단일셀 / bifacial | 14,024 | 97,808 | 14,024 | ✅ |

**6분기 모두 `대각 슬롯 수 == Ns`다.** 구조적 이유가 있다 — 조립 코드가 대각을

```python
J += csr_matrix((diag, (np.arange(Ns), np.arange(Ns))), shape=(Ns, Ns))
```

로 **통째로** 더하므로(`2L_FEST.py:5211-5213` 등) 값이 0인 대각도 저장 슬롯으로
남는다. 그러므로 시간 항은 **기존 슬롯에 값을 더하는 것**이고 `nnz`가 움직이지
않는다. §2의 판정이 이 저장소의 실제 조립 방식 위에서 성립한다.

> ⚠ **이것은 "지금 그렇다"이지 "항상 그렇다"가 아니다.** 누군가 그 조립을
> *"0인 대각은 빼고 넣자"* 로 최적화하면 조건이 깨진다.
> `test_every_diagonal_entry_is_structurally_present`가 그때 먼저 실패한다.
> **그 경우 고칠 것은 테스트가 아니라 §2의 판정이다.**

#### 함께 확인된 것 세 가지

| # | 사실 | 왜 필요한가 |
|---|---|---|
| 1 | 한 solve 안에서 뉴턴 반복이 2~29회 돌아도 **희소성 패턴이 하나**다 | 반복마다 달라지면 "패턴 불변"이라는 말 자체가 성립하지 않는다 |
| 2 | `Vb`를 0.5 → 0.9로 바꿔도 **패턴이 같다** | `calc_iv_transient`는 시간에 따라 `Vb`를 훑는다(§3). 스텝마다 재조립이 강제되지 않는다는 뜻 |
| 3 | **노드마다 다른 다이오드 계수**(`spatial_j01`)를 걸어도 패턴이 같다 | 시간 항도 노드마다 다른 값을 대각에 더한다. 같은 성격의 항이 이미 하나 있고 구조를 안 바꾼다는 실측 방증 |

3번은 **증명이 아니라 방증**이다 — 다이오드 항은 대각과 몇몇 off-diagonal 블록에
들어가고 시간 항은 대각에만 들어간다. 결정적 근거는 위의 대각 완비성이다.

#### 계획서와 달라진 것 — `indptr` 대신 좌표 집합

§2는 *"희소성 패턴(`J.nnz`, `J.indptr`)이 불변임을 고정"* 하라고 적었다.
**`indptr`은 쓰지 않았다** — 저장 포맷(CSR/CSC)에 따라 값이 달라져서 포맷이
바뀌면 물리와 무관하게 핀이 깨진다. 대신 `(row, col)` 쌍을 사전식으로 정렬해
sha256을 떴다. **포맷과 무관하고 정보량은 같거나 많다.**

리터럴 핀(`nnz` + 해시)은 **메시에 의존**하므로 `bit_pin_gate`로 낮췄다 —
메시는 Qhull(Delaunay)을 거치기 때문이다. 위 표의 **구조 불변식 4종**(대각 완비 ·
반복 내 단일 패턴 · `Vb` 무관 · 맵 무관)은 리터럴에 의존하지 않으므로 **어느
머신에서도 strict로 돈다.**
