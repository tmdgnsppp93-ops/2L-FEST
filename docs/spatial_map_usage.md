# 공간 분포 맵 — 사용 안내

> **성격**: 사용 설명서. 규범 문서가 아니다 — 규약의 근거와 확정 이력은
> `docs/spatial_map_convention.md`에 있고, 여기는 **그 규약대로 쓰는 법**만 적는다.
> 둘이 어긋나면 규약 문서가 맞다.
>
> **예제 파일**: `examples/spatial_maps/` (5종)
> **적용 버전**: v28.61 이상. v28.60 이하에서는 **결과를 믿으면 안 된다** — §9 참조.
> `rsh`(션트)는 **v28.62** 이상.

---

## 1. 이게 무엇인가

셀 면 안에서 물성이 **균일하지 않은** 상황을 2D 행렬 파일로 넣는다. 예를 들어

- 라미네이션 압력이 중앙만 강해서 **접촉저항이 자리마다 다른** 경우
- 절단면 손상 때문에 **가장자리 재결합이 큰** 경우
- 솔라 시뮬레이터 램프가 한쪽만 밝아서 **광생성이 기울어진** 경우

대상은 다섯 가지다. 각각 독립이며, 다섯을 동시에 걸 수도 있다.

| 대상 | GUI 라벨 | 무엇에 곱하는가 | 값이 크면 |
|---|---|---|---|
| `j01` | J01 배율 | n=1 다이오드 포화전류 | 재결합 **증가** (나쁨) |
| `j02` | J02 배율 | n=2(공핍층) 포화전류 | 재결합 **증가** (나쁨) |
| `gen` | 광생성 배율 | 전면 광생성 전류 | 광전류 **증가** (좋음) |
| `rc` | 접촉 비저항 배율 | **접촉 저항** | 접촉 **악화** (나쁨) |
| `rsh` | 션트 저항 배율 | **션트 저항 Rsh** | 누설 **감소** (좋음) |

> ### ⚠ `rc`와 `rsh`는 방향이 반대로 읽히기 쉽다
>
> 둘 다 맵이 **저항**을 곱한다(컨덕턴스를 나눈다).
>
> | 대상 | `0.5`이면 | `2.0`이면 |
> |---|---|---|
> | `rc` | 접촉저항 절반 → **잘 눌린 곳** | 접촉저항 두 배 → **덜 눌린 곳** |
> | `rsh` | Rsh 절반 → 누설 2배 → **션트 지점** | Rsh 두 배 → 누설 절반 → **깨끗한 곳** |
>
> "압력이 세니까 값을 크게", "션트가 심하니 값을 크게"라고 쓰면 **정확히 반대
> 결과**가 나온다. 엔진이 이 둘을 `SPATIAL_INVERTED_TARGETS`로 따로 묶고 있고,
> GUI가 그 목록을 보고 힌트를 **앰버(주황)** 로 강조한다 — 힌트가 주황색이면
> 방향이 뒤집히는 대상이라는 뜻이다.
>
> 나머지 셋은 "값이 크다 = 그 물성이 크다"로 일관되며, `gen`만 그것이 좋은 방향이다.
>
> ### ⚠⚠ `rsh`는 Griddler와 곱셈 방향까지 반대다
>
> Griddler는 shunt를 **컨덕턴스**(`G_shunt` [S/cm²])로, 2L-FEST는 **저항**
> (`Rsh` [Ω·cm²])으로 둔다. 두 상태량은 역수이므로 **배율 파일도 역수여야 한다.**
>
> ```
> Griddler용 맵 값 g   ↔   2L-FEST용 맵 값 1/g
> ```
>
> **Griddler의 shunt 맵을 그대로 넣으면 누설이 심한 자리가 가장 깨끗한 자리로
> 계산된다.** 오류도 경고도 없이 그렇게 된다. 근거와 상세는
> `docs/spatial_map_convention.md` §7.

### 두 가지 적용 범위 제한

- **`rc`는 금속 노드에서만 효과가 있다.** 패시베이션 영역에는 접촉 자체가 없으므로
  그 자리의 값은 결과에 반영되지 않는다. 핑거·버스바를 덮지 않는 칸에 무엇을 적든
  무시된다.
- **`gen`은 전면 입사광에만 곱해진다.** 양면 셀의 후면 입사광
  (`bifacial_gain × rear_illum_frac`)은 별개 광원이라 곱하지 않는다. 후면 조도
  불균일은 이 맵으로 표현할 수 없다.
- **`rsh`는 top·bottom 서브셀에 같은 맵이 걸린다.** 탠덤에서 `Rsh_top`과
  `Rsh_bot`이 같은 배율을 받는다 — 션트는 보통 웨이퍼를 관통하는 경로라
  서브셀별로 다른 분포를 주장할 근거가 없기 때문이다. 서브셀별 분포가 필요하면
  별건이다.

## 2. 파일 형식

```
# 이 줄은 주석이다 (# 로 시작하는 줄과 빈 줄은 건너뛴다)
1.00, 1.20, 1.20, 1.00
1.10, 1.40, 1.40, 1.10
1.10, 1.40, 1.40, 1.10
1.00, 1.20, 1.20, 1.00
```

| 항목 | 규칙 |
|---|---|
| 확장자 | `.txt` / `.csv` (내용만 본다) |
| 인코딩 | UTF-8 (BOM 있어도 된다) |
| 구분자 | **자동 판별** — 파일 어딘가에 콤마가 있으면 콤마, 없으면 공백·탭 |
| 주석·빈 줄 | `#`로 시작하는 줄과 빈 줄은 데이터가 아니다. 몇 줄이든 어디든 가능 |
| 행 = y, 열 = x | **첫 데이터 줄 = 셀의 아래쪽(y=0)**, 첫 열 = 왼쪽(x=0) |
| 값 | **절대 배율.** 파일의 수가 그대로 배율이다 — 정규화하지 않는다 |
| 최소 크기 | **2×2 이상.** 보간이 두 점을 요구한다 |
| 열 개수 | 모든 행이 같아야 한다 |
| 큰 행렬 | 512를 넘으면 "느려질 수 있다" 경고만 뜬다(거부는 아니다) |

### 거부되는 값 — 조용히 고치지 않는다

`0` · **음수** · `NaN` · `inf`는 **로드 시점에 거부**하고, 어느 파일 몇 행 몇 열의
어떤 값인지 적어서 알려준다.

```
edge.txt: 데이터 행 3, 열 5의 값이 0.0이다. 배율은 유한하고 양수여야 한다 —
0·음수·NaN·inf는 자동으로 고치지 않고 거부한다.
```

클램프하거나 1.0으로 치환하지 않는 이유는 분명하다 — 솔버가 도는 중에 터지면
사용자는 **어느 파일의 어느 칸이 문제인지 알 수 없다.** 검증은 파일을 읽는
자리에서 끝낸다.

> "완전히 그늘진 곳"을 표현하려고 `gen`에 `0`을 넣고 싶을 수 있다. 배율 0은 그
> 노드의 광전류를 없애는 것이 아니라 **모델을 특이하게** 만든다. `0.01` 같은 작은
> 양수를 쓸 것.

### 격자는 꼭짓점 정렬 — 모서리 값이 셀 모서리에 정확히 놓인다

`n×n` 행렬은 셀을 `n` 등분한 **칸**이 아니라 `n` 개의 **격자점**이다.
4×4 행렬이 30 × 30 mm 셀에 놓이면 간격은 `30/(4−1) = 10 mm`이고, 네 모서리 값이
셀의 네 꼭짓점에 정확히 앉는다. 그 사이는 쌍선형 보간이다.

```
y=30mm ┤ 3.0   1.0   1.0   9.0     ← 파일의 마지막 데이터 줄
y=20mm ┤ 1.0   1.0   1.0   1.0
y=10mm ┤ 1.0   1.0   1.0   1.0
y= 0mm ┤ 2.0   7.0   1.0   5.0     ← 파일의 첫 데이터 줄
       └────┬─────┬─────┬─────┬──
          x=0    10    20    30 mm
```

> **텍스트 편집기로 열면 위아래가 뒤집혀 보인다.** 사람은 첫 줄을 위로 읽지만
> 여기서는 아래다. GUI 미리보기가 `origin='lower'`로 그리는 이유이고, **버그가
> 아니다.** 방향이 헷갈리면 `examples/spatial_maps/gradient_gen.txt`를 걸어
> 미리보기에서 왼쪽 아래가 가장 어두운지 보면 된다.

## 3. 예제 파일

`examples/spatial_maps/` — 각 파일 맨 위에 용도와 값의 의미가 주석으로 있다.

| 파일 | 크기 | 대상 | 내용 |
|---|---|---|---|
| `uniform_4x4.txt` | 4×4 | 아무거나 | 전부 1.0. **동작 확인용** |
| `center_pressed_rc.txt` | 8×8 | `rc` | 중앙 0.58 → 모서리 2.00. 중앙이 잘 눌린 압력 분포 |
| `edge_defect_j01.txt` | 8×8 | `j01` | 안쪽 1.00 → 변 2.50 → 모서리 4.00. 가장자리 손상 |
| `gradient_gen.txt` | 8×8 | `gen` | 왼쪽 아래 0.90 → 오른쪽 위 1.14. 조도 기울기 |
| `local_shunt_rsh.txt` | 8×8 | `rsh` | 한 지점만 0.15(누설 6.7배), 나머지 1.00. 국부 션트 |

> ### ⚠ `uniform_4x4.txt`는 맵을 "끄는" 파일이 아니다
>
> 값이 전부 1.0이지만 엔진은 노드마다 **실제로 1.0을 곱한다.** 무맵 경로가
> 비트 단위로 같은 근거는 *"1을 곱한다"* 가 아니라 **"곱셈을 아예 하지 않는다"**
> 이다. 맵을 완전히 떼려면 GUI의 **[해제]** 를 쓸 것.

## 4. GUI 사용 순서

1. **STEP 3 (Diode)** 사이드바에서 보라색 **SPATIAL MAPS** 카드를 찾는다.
   카드에 `5개 중 n개 적용`으로 현재 상태가 보인다. (총 개수는
   `len(SPATIAL_TARGETS)`에서 온다 — 대상이 늘면 이 숫자도 같이 는다.)
2. **[공간 분포 맵 설정...]** 버튼 → 설정 창이 뜬다. 대상마다 카드가 하나씩이고
   카드마다 **[불러오기...] [해제] [미리보기]** 가 있다.
   카드 목록은 **스크롤된다** — 창을 줄여도 아래 카드에 닿을 수 있다.
   마우스 휠은 목록 위에서만 듣는다(오른쪽 미리보기 위에서 굴려도 목록은
   움직이지 않는다).
3. 파일을 처음 만든다면 창 오른쪽 위 **[형식 도움말...]** 을 먼저 연다.
   - 복사해서 바로 고쳐 쓸 수 있는 **예시 4x4** ([예시 복사] 버튼)
   - 로더가 실제로 거부하는 조건 그대로의 **규칙**
   - **방향 주의** — `rc`·`rsh`는 값이 클수록 좋아진다(§6, §9)
   - 배포된 **예제 폴더 경로**와 그 안의 파일 목록
4. **[불러오기...]** 로 파일을 고른다. 대화상자는 `examples/spatial_maps/`
   에서 열리므로, 처음이라면 거기 있는 예제부터 하나 걸어 보면 된다.
   - 성공하면 상태줄에 `공간 분포 맵 적용 [j01]: 파일명 (8x8, 1~4)`
   - 실패하면 **어디가 왜 잘못됐는지** 적힌 오류 창이 뜬다(§2)
5. **[미리보기]** 로 반드시 눈으로 확인한다. **y가 위로 가도록** 그리므로,
   의도한 그림과 위아래가 맞는지 여기서 판정한다. 파일과 반대로 보이는 것이 정상.
   그림 아래에 `최소 / 최대 / 평균 (ny x nx개 값)` 이 숫자로 함께 뜬다 —
   **그림만으로는 값을 못 읽는다.** 컬러맵이 자동 정규화하므로 전부 2.0인 맵과
   전부 1.0인 맵이 화면에서 똑같이 보인다. 배율의 절대 크기는 이 숫자로 본다.
6. **COMPARE를 다시 실행한다.** 맵을 걸거나 해제하면 상태줄이
   `적용하려면 COMPARE를 다시 실행하세요` 라고 알린다 — 이전 결과는 자동으로
   갱신되지 않는다.

해제는 **[해제]** 버튼이다. 1.0짜리 파일을 다시 불러오는 것과 다르다(§3).

## 5. 어느 바이어스에서 효과가 보이나

**맵을 걸었는데 Jsc가 안 변한다고 해서 안 걸린 것이 아니다.** 대상마다 효과가
드러나는 동작점이 다르다.

이 저장소의 시험용 소형 셀(2 × 2 mm, 핑거 8 + 버스바 1, 기본 탠덤 파라미터,
`Voc ≈ 1.947 V`)에서 예제 파일을 걸었을 때의 단자 전류 변화:

| 걸린 맵 | Vb = 0 (Jsc) | Vb = 0.85·Voc (MPP 부근) | Vb = 0.95·Voc |
|---|---:|---:|---:|
| `gen` ← `gradient_gen.txt` | **+2.00 %** | +2.05 % | +3.14 % |
| `j01` ← `edge_defect_j01.txt` | −0.000 % | −0.70 % | **−22.8 %** |
| `rc` ← `center_pressed_rc.txt` | −0.000 % | −0.006 % | −0.16 % |
| `rsh` ← `local_shunt_rsh.txt` | −0.001 % | −0.19 % | −0.29 % |

읽는 법:

- **`gen`은 Jsc부터 바로 보인다.** 변화량(+2.0 %)이 맵의 **평균값**(1.020)과 거의
  같다 — 광생성은 전류에 직접 더해지기 때문이다.
- **`j01`/`j02`는 Jsc에서 사실상 안 보이고 Voc 쪽에서 폭발한다.** 재결합은 다이오드
  항이라 전압이 붙어야 커진다. **가장자리 손상을 Jsc로 진단하려 하면 안 된다.**
- **`rc`는 전류가 클수록 보인다.** 위 표에서 작게 나오는 것은 이 시험 셀의 접촉저항
  자체가 작아서이며, 실제 셀에서는 훨씬 크다.
- **`rsh`는 전압이 붙을수록 보인다.** 션트 전류가 `V / Rsh`라 Jsc에서는 거의 0이다.
  `j01`만큼 폭발하지는 않는다 — 션트는 전압에 **선형**이고 다이오드는 지수이기
  때문이다. 이 예제는 한 지점만 눌린 국부 션트라 평균 배율이 0.90이다.
- `rc` 예제가 **음수**인 것도 확인할 것 — 중앙은 좋아졌지만 맵의 평균이 1.17
  (평균적으로 더 나쁨)이라 순효과는 손해다. **"중앙만 잘 눌리면 이득"이 아니다.**

> 위 수치는 **소형 시험 셀의 값이다.** 제품 셀의 수치로 인용하면 안 된다.
> 방향과 "어느 동작점에서 보이는가"만 가져갈 것.

## 6. 실제 활용 예시

### 6-1. 라미네이션·프린팅 압력 분포 → `rc`

압력 필름(Fuji Prescale 등)이나 압력 센서 매트의 스캔을 격자로 줄여 **저항 배율**로
바꾼다. 압력 → 접촉저항 관계는 공정마다 다르므로 **몇 점을 실측해 맞춘 뒤** 쓸 것.

```
압력 높음 → 접촉저항 낮음 → 값 < 1.0     ← 방향을 여기서 뒤집는다
압력 낮음 → 접촉저항 높음 → 값 > 1.0
```

`examples/spatial_maps/center_pressed_rc.txt`가 이 형태다.

### 6-2. 막 두께 편차 → `gen` 또는 `rc`

- **반사방지막/투명전극 두께 편차** → 흡수·반사가 달라진다 → `gen`.
  두께 맵을 광학 계산에 넣어 얻은 **상대 광전류**를 배율로 쓴다.
- **투명전극(TCO) 두께 편차** → 면저항이 달라진다. ⚠ 이것은 **`rc`가 아니다.**
  `rc`는 금속-반도체 **접촉** 저항이고 면저항(횡전도)은 공간 분포 대상이 아니다
  (규약 §5). 지금은 면저항 맵을 넣을 방법이 없다.

### 6-3. 가장자리 손상 → `j01`

레이저 스크라이빙·절단면 손상, 가장자리 패시베이션 열화. PL/EL 이미지에서 테두리가
어둡게 나오는 그것이다. `edge_defect_j01.txt` 참고.

효과는 **Voc와 FF**에서 본다(§5). Jsc는 거의 그대로다.

### 6-4. PL/EL 이미지 → `j01`

발광 이미지의 어두운 곳이 재결합이 큰 곳이다. 이미지를 격자로 줄이고 **밝기의
역수 계열**로 배율을 만든다.

⚠ 이미지 파일을 직접 넣는 기능은 **아직 없다**(§8). 지금은 이미지를 밖에서
숫자 행렬로 바꿔 txt로 저장해야 한다. 그리고 **이미지 좌표계는 위에서 아래로**
내려가는 것이 관례이므로, 그대로 쓰면 위아래가 뒤집힌다 — 저장하기 전에 뒤집을 것.

### 6-5. 국부 션트 → `rsh`

스크라이빙 잔여물, 금속 침투, 핀홀. EL 이미지에서 한 점만 어둡고 **저전압 쪽
FF가 무너지는** 형태로 나타난다. `local_shunt_rsh.txt` 참고.

```
누설 심함 → Rsh 낮음 → 값 < 1.0     ← 방향을 여기서 뒤집는다
깨끗함    → Rsh 높음 → 값 > 1.0
```

암전류(dark I-V)의 저전압 기울기에서 국부 Rsh를 역산해 맞추는 것이 실무적이다.
**Griddler에서 만든 shunt 맵을 가져올 때는 역수를 취할 것**(§1).

### 6-6. 조도 불균일 → `gen`

솔라 시뮬레이터의 공간 불균일(Class A라도 ±2 %), 램프 노후, 마스크 그림자.
`gradient_gen.txt`가 이 형태다.

측정한 조도 맵을 **1 Sun 대비 비율**로 넣는다. 평균이 1.0이 되도록 맞추지 않으므로,
평균 조도까지 반영된다는 점에 주의할 것 — 그것이 의도가 아니면 미리 나눠 둘 것.

## 7. 해상도 — 몇 칸으로 할 것인가

노드 사이는 **쌍선형 보간**이라, 격자가 성기면 값이 넓게 번진다.

폭 `w`짜리 특징(가장자리 띠, 국부 결함)을 표현하려면 **격자 간격 ≤ w**가 되도록
칸 수를 정한다.

```
셀 폭 20 mm, 폭 1 mm 가장자리 띠를 원한다
  → 격자 간격 1 mm → 칸 수 = 20/1 + 1 = 21   (n×n 행렬은 n−1 등분이다)
```

`edge_defect_j01.txt`는 8×8이라 간격이 셀 폭의 1/7이다. 그래서 바깥 줄의 큰 값이
안쪽으로 그만큼 번진다 — 예제로는 충분하지만 **정량 해석에는 격자를 키울 것.**

512를 넘으면 경고가 뜬다. 노드마다 보간을 하므로 실행이 느려진다.

## 8. 아직 안 되는 것

| 항목 | 상태 |
|---|---|
| **이미지 입력**(jpg/tif/bmp) | **미구현.** 규약이 반대다(상대값·평균 1 정규화)라 별도 함수로 둘 예정. Pillow 의존성이 저작권 등록 자료의 구성요소 기재와 얽혀 **등록 이후**로 미뤘다 |
| **면저항(`Rs`) 공간 분포** | 대상 아님. 주입 지점이 강성행렬 조립 단계라 성격이 다르다(규약 §5) |
| **`Rs_vert_*` 공간 분포** | 계층이 다르다(터미널 사후처리). 규약 §5의 이중 계산 재검토가 선행 |
| **서브셀별 `rsh` 분포** | `rsh` 맵은 top·bottom에 **같은 배율**이 걸린다(§1). 서브셀별로 다른 분포를 주장할 근거가 아직 없다 |

> **션트(`Rsh`) 공간 분포는 v28.62에서 구현됐다** — 위 표에서 내려왔다.
> 우선순위 0의 결함이 해소되기 전에는 *"같은 공백을 하나 더 복제한다"* 는 이유로
> 보류했었고, 해소된 뒤에 추가했다.

## 9. ⚠ 반드시 알고 쓸 것 두 가지

### 9-1. Griddler와 규약이 같은지는 **확인되지 않았다**

같은 파일을 Griddler에 넣어 대조하는 절차를 계획했으나 **수행하지 못했다** —
공간 분포 입력이 Griddler **유료판(PRO) 전용**이라 무료판에는 진입점 자체가 없다.

| 규약 | 2L-FEST 확정값 | Griddler와 같은가 |
|---|---|---|
| 행 방향 | 첫 데이터 줄 = `y=0` (아래) | **미확인** |
| 격자 정렬 | 꼭짓점 정렬 | **미확인** |
| 값 해석 | 절대값(정규화 없음) | 매뉴얼 §3.1 기준 같을 것으로 보이나 **미확인** |

따라서 이 기능은 **"같은 목적을 같은 입력 형식으로 달성"** 이지
**"같은 파일이 양쪽에서 같은 결과"** 가 아니다.

> **발표·보고에서 Griddler 교차검증으로 인용하면 안 된다.**

대조 절차와 기대값 8점은 PRO 확보 대비로 보존해 두었고
(`docs/crosscheck/2026-08-18-spatial-map-griddler.md`), 대조 결과가 규약과 어긋나면
**보정은 파일 로더 안에서만** 한다 — 계산 엔진은 건드리지 않는다.

### 9-2. v28.60 이하에서 나온 값은 신뢰할 수 없다

v28.61 이전에는 `j01`/`j02`/`gen` 세 맵이 **프로덕션 tandem 설정 전부에서 잔차에
반영되지 않았다.** 그런데 보고되는 전류는 맵을 적용해 다시 계산했기 때문에
**숫자가 바뀌어서 겉보기에는 작동하는 것처럼 보였다.**

**v28.60 이하에서 맵을 걸고 얻은 결과가 있다면 다시 계산할 것.**
경위는 `docs/spatial_map_convention.md` §6.

## 10. 스크립트에서 쓰기

GUI 없이 쓸 수 있다. GUI도 같은 함수를 부른다.

```python
import importlib.util, sys

spec = importlib.util.spec_from_file_location("fest", "2L_FEST.py")
fest = importlib.util.module_from_spec(spec)
sys.modules["fest"] = fest
spec.loader.exec_module(fest)

dp = fest.DiodeParams()

# 불러오기 — 값 검증은 이 줄에서 끝난다
sm = fest.load_spatial_map_txt("examples/spatial_maps/edge_defect_j01.txt")
print(sm.load_report)        # 경로·형상·구분자·건너뛴 줄 수·경고

# 붙이기 / 조회 / 떼기
fest.set_spatial_map(dp, "j01", sm)
fest.get_spatial_map(dp, "j01")
fest.clear_spatial_map(dp, "j01")      # ← 반드시 이것. 1.0짜리 맵으로 대체 금지
```

> ### ⚠ 맵은 **인스턴스**에만 붙인다
>
> `spatial_*`는 `DiodeParams`의 **클래스 속성**이라 클래스에 직접 붙이면 이후
> 만들어지는 모든 인스턴스가 그 맵을 물려받는다 — 전역 누출이라 되돌리기 어렵고
> *"맵을 지웠는데 결과가 그대로"* 로 나타난다. `set_spatial_map`이 클래스를 받으면
> 즉시 거부하므로, **`setattr`을 직접 쓰지 말고 이 함수들을 쓸 것.**
